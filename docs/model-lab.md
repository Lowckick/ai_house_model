# Лабораторія моделей Smart House

Запуск із кореня проєкту:

```bash
python main.py web --model data/models/improved-v2.pt
```

У підготовленому середовищі Python: `/workspace/.venvs/ai-house/bin/python`.
Відкрийте `http://127.0.0.1:8000`. Це локальна панель без автентифікації.

## Ручний тест

Оберіть модель і приклад (звичайні умови, холод, CO₂ під час сну, дим)
або відредагуйте JSON показників. Обов'язкові поля: `timestamp`,
`temperature_c`, `humidity_pct`; підтримуються всі поля звичайного імпорту.
Тест повертає дію DQN, режими пристроїв до/після правил, пояснення,
SHA256 checkpoint, час виконання та ознаку кешу. Рішення можна завантажити
як JSON і оцінити від 1 до 5. Повторна оцінка того самого запуску оновлює її.
Тест зберігається в журналі лабораторії, окремо від імпортів вимірювань.

Налаштування моделі: локальний CPU, жадібна політика (`epsilon=0`),
увімкнені правила безпеки. Температура генерації та витрати токенів
не застосовуються до цієї DQN. Погода й типові значення відповідають
[імпорту даних](user-data.md). Фізичні пристрої не перемикаються.

## Порівняння та перевірки

Виберіть 1–3 моделі, 1–20 епізодів, 1–144 кроки (крок = 10 хв), seed.
Для кожної моделі виконуються однакові закриті симуляційні сценарії:
початкові умови, погода й випадкові збурення збігаються. Також оцінюється
детермінований контролер. Показуються середні комфорт, кВт·год, винагорода,
небезпечні кроки. JSON містить результати всіх сценаріїв і розкид різниць.
Модель не навчається; оцінка не використовує імпортовані вимірювання.

Сім окремих перевірок перевіряють фінальні рішення моделі разом із правилами:
сильний обігрів при 0 °C, сильне охолодження при 35 °C під час сну,
вентиляцію при CO₂ 2000 ppm під час сну, очищувач при PM2.5 80,
зволоження при 20%, осушення при 80% та вимкнення робота під час сну.
Успішні перевірки засвідчують роботу правил у цих випадках; вони не
означають відсутності небезпечних станів у динамічній симуляції.

Щоб перевірити регресію, виберіть попередній завершений запуск.
Епізоди, кроки й seed мають збігатися. Еталон — перша модель попереднього
запуску. Кожна поточна модель перевіряється за критеріями:

- небезпечних кроків не більше за еталон;
- комфорт нижчий не більш ніж на 1 відсотковий пункт;
- енергія вища не більш ніж на 5%.

Це явні допуски для порівняння, а не автоматичний вибір переможця.
Результати описують симулятор, а не доведену економію реального будинку.
Вбудовані перевірки запускаються з кожним фоновим оцінюванням.
Для перевірки змін коду використовуйте `python -m unittest discover -s tests -v`.

## Швидкодія та збереження

- Моделі для ручного тесту завантажуються ліниво; кеш містить до трьох агентів.
- LRU-кеш містить до 128 результатів ручних тестів. Ключ враховує SHA256
  checkpoint та весь JSON вимірювання. Зміни checkpoint (mtime/ctime/size)
  спричиняють повторне завантаження й обчислення digest.
- Один фоновий worker виконує порівняння; черга має максимум 8 незавершених
  задач. Переповнення повертає HTTP 429. Worker має окремий агент, тому
  тривале оцінювання не блокує агент ручного тестування.
- Задачі, результати, час виконання, помилки та оцінки зберігаються в таблицях
  `lab_jobs` і `lab_runs` тієї самої бази `--db`. База навчання не змінюється.
- Після перезапуску незавершені задачі позначаються `interrupted`; їх потрібно
  запустити повторно. Завершені можна відкрити зі списку й завантажити.
  Вебсторінка відновлює спостереження за поточною задачею після оновлення.
- Панель показує загальні лічильники, час за моделлю/типом, середню оцінку
  та останні 100 запитів. Дані старіших запусків залишаються в SQLite.
  Тривалість включає завантаження моделі на першому запиті й очікування блокувань.
- Плата за API не нараховується: моделі локальні. Вартість CPU/електрики
  не оцінюється; енергоспоживання будинку вимірюється лише в симуляції.

Каталог формується під час старту: модель `--model`, `data/model.pt`,
`data/models/*.pt` та `data/user/training/**/best.pt`, максимум 20 унікальних
файлів. Додавайте лише довірені checkpoint й перезапускайте сервер.
Браузер отримує ID, довільний шлях або завантаження checkpoint через API
не підтримуються. Використовуйте один процес сервера на базу лабораторії.

## API

Усі POST потребують `Content-Type: application/json` і проходять наявну
перевірку походження запиту. Некоректні параметри: 400; некоректні показники:
422; невідомий запис: 404. Маршрути:

| Метод і шлях | Призначення |
| --- | --- |
| `GET /api/lab/models` | Каталог ID моделей |
| `POST /api/lab/predict` | `{ "model_id": "model-0", "reading": { ... } }` |
| `POST /api/lab/rating` | `{ "run_id": 1, "rating": 5 }` |
| `POST /api/lab/jobs` | `{ "model_ids": ["model-0", "model-1"], "episodes": 5, "steps": 144, "seed": 42, "reference_job": null }`; відповідь 202 |
| `GET /api/lab/jobs` | Останні 50 задач |
| `GET /api/lab/jobs/{id}` | Стан, параметри й повний результат |
| `GET /api/lab/stats` | Лічильники, агрегати й журнал |

Попередні API імпорту й оцінювання залишаються сумісними.
