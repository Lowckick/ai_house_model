# Власні вимірювання та порівняння систем

## Запуск вебінтерфейсу

Із кореня репозиторію після встановлення `requirements.txt`:

```bash
python main.py web
```

Сервер слухає `127.0.0.1`, порт `8000`. Відкрийте цю адресу в браузері на
машині, де працює сервер, або скористайтеся переадресацією порту свого
середовища розробки. Зупинка — Ctrl-C. Це локальний інструмент розробки
без облікових записів; прив’язку `--host 0.0.0.0` використовуйте лише в довіреній
мережі або за проксі з автентифікацією.

У підготовленому хмарному середовищі:

```bash
/workspace/.venvs/ai-house/bin/python main.py web \
  --model data/model.pt \
  --db /workspace/.onboarding/ai-house/data/measurements.db
```

Можна змінити `--host`, `--port`, `--model`, `--db`. Додаткові вебзалежності,
ключі API та доступ до інтернету для цих функцій не потрібні.
Використовуйте довірені моделі. Сервер завантажує модель під час першого
імпорту/оцінки й повторно використовує її; після заміни checkpoint перезапустіть сервер.

## Завантаження та перевірка

1. Оберіть JSON, CSV або TXT-файл. Приклад JSON можна завантажити кнопкою
   на сторінці; файли обох форматів є в `examples/`.
2. Натисніть **Перевірити файл**. Дані на цьому етапі не зберігаються.
3. Перегляньте помилки, попередження та попередній перегляд перших 10 коректних
   записів. Повний звіт можна завантажити в JSON. При помилці виправте файл
   і перевірте його повторно.
4. Натисніть **Зберегти та отримати рекомендації**. Усі записи й рекомендації
   зберігаються однією транзакцією; при некоректному файлі часткового імпорту немає.
5. Перегляньте графік температури/вологості/CO₂, рекомендації обох систем
   і пояснення. Таблиця показує перші 200 записів; експорт JSON містить усі.

Обмеження: 5 МіБ, до 5000 записів, UTF-8 (BOM дозволено).
TXT та CSV — таблиці з комами й заголовком, а не довільний текст.
Схема показників і одиниці наведені в розділі README «Завантаження власних показників».
Обов’язкові поля: `timestamp`, `temperature_c`, `humidity_pct`.

Перевіряються всі записи та всі підтримані поля: наявність обов’язкових,
назви, числові типи, скінченність, діапазони, ціла кількість мешканців,
формат часу та активності. Дублікати назв колонок CSV та ключів JSON відхиляються.
Звіт повідомляє номер запису, а не фізичний номер рядка файлу.

Попередження не блокують імпорт: пропущені показники й типові значення,
час без часового поясу, повторення часу, зворотний порядок часу та перевищення
безпечних меж датчиків. Записи залишаються у вихідному порядку; дублікати
не видаляються. Для перевірки порядку час без поясу вважається UTC;
часові ознаки моделі використовують годину, записану у файлі.

Відсутні показники приміщення замінюються `IndoorState` defaults. Температура
кімнат дорівнює загальній; за наявності мешканців усі кімнати вважаються зайнятими.
Поточні режими пристроїв для незалежного аналізу кожного запису — `DeviceState`
за замовчуванням. Зовнішня погода фіксована: 15 °C, 60% вологості, вітер 0,
хмарність 50%, опади та UV 0, день 06:00–20:00 за часом запису.
Ці припущення показані на сторінці та в експорті; вони впливають на рекомендації.

## Пояснення рекомендацій

Для кожного запису збережено:

- `model_devices` — початкову дію з найбільшою Q-оцінкою, без випадкового вибору;
- `recommended_devices` — остаточні режими після правил;
- `deterministic_devices` — результат простого контролера на тому самому вимірюванні;
- `explanations` — джерело, етап правила, поле, попереднє й нове значення та пояснення.

Пояснення моделі не є атрибуцією ознак нейромережі: причин її Q-оцінки ми
не виводимо. Правила пояснюють лише фактичні зміни дій, наприклад
«CO₂ 1800 ppm > 1500: вентиляція щонайменше 2». Якщо модель вже обрала достатню
вентиляцію, зміни правила для цього поля немає.

Порядок: освітлення → жалюзі → охорона → сон → безпека.
Безпека має найвищий пріоритет: сон не знижує потрібну вентиляцію при
високому CO₂ і не скасовує захист від небезпечної температури.
Проміжні зміни також видно в поясненнях; остаточна дія — `recommended_devices`.

## Історія

Типово дані зберігаються в окремій SQLite-базі `data/user/measurements.db`
(каталог виключено з Git). `data/training.db` і навчена модель не змінюються.

Історія містить імпорти з назвою файла, часом завантаження, нормалізованими
вимірюваннями, рекомендаціями, звітом перевірки та SHA-256 файла й моделі.
Хеш файла обчислюється з декодованого UTF-8 тексту, а не оригінальних байтів BOM.
Повторне завантаження створює окремий імпорт. У вебісторії показано останні
100 імпортів і останні 100 оцінок; старіші записи залишаються в базі.
Натисніть запис, щоб відкрити його та завантажити JSON. Історія зберігається
після перезапуску за умови використання того самого `--db`.

## Оцінка моделі

Натисніть **Порівняти системи** або виконайте CLI-команду нижче.
Типові параметри: 5 епізодів × 144 кроки, по 10 хвилин на крок, seed 42.
Межі: 1–20 епізодів, 1–144 кроки, seed 0–4294967275.

Це парна симуляція із замкненим контуром: кожен контролер впливає на власну
копію фізичного стану. У кожній парі однакові початкові стани, погода,
кількість мешканців та послідовності випадкових збурень фізики/присутності.
Умовний час просувається на 10 хвилин. Протокол 2 використовує test-сценарії
2026 року з різними сезонами, початковими показниками й кількістю мешканців.
Повні параметри сценаріїв записані в `trials[].scenario`; системний час на
результат не впливає. Навчання під час оцінки не виконується.

Підтримуються legacy-моделі з 1920 діями та нова гібридна політика
`residual_v1` з 19 діями-корекціями над простим контролером. Версії дій,
протоколу та винагороди записані у звіті. Обидва контролери оцінюються
поточною `comfort_safety_v2`; старі збережені оцінки можуть використовувати
іншу винагороду та сценарії, тож для порівняння слід запустити їх повторно.
[Навчання нової моделі](training.md).

Простий детермінований контролер:

| Пристрій | Правило |
| --- | --- |
| HVAC | Обігрів нижче 20 °C, охолодження вище 24 °C, інакше вимкнено |
| Вентиляція | Рівень 1 при CO₂ > 1000 ppm |
| Очищувач | Рівень 1 при PM2.5 > 12 мкг/м³ |
| Вологість | Зволоження < 40%, осушення > 60% |
| Робот | Прибирання при забрудненні > 30%, крім сну |

Обидві системи мають однакові додаткові правила освітлення, жалюзі,
охорони, сну та остаточного захисту. Порівнюється **модель + правила**
з **детермінованим контролером + тими самими правилами**.

Метрики наведено в середньому за епізодами:

| Метрика | Розрахунок | Краще |
| --- | --- | --- |
| Комфорт | Середній `comfort_score` симулятора, 0–100 | Більше |
| Енергія | Сума потужностей × 10/60, кВт·год | Менше |
| Винагорода | Сума `RewardFunction`, включно зі штрафом за перемикання | Більше |
| Небезпечні кроки | Кількість кроків після дії, де T < 5 або > 32 °C, CO₂ > 1500 ppm чи PM2.5 > 55 мкг/м³ | Менше |

Крок із кількома порушеннями рахується один раз. Різниця завжди означає
«модель мінус детермінована система». Повний JSON містить кожен епізод,
розкид парних різниць (`paired_delta_stddev`, null для одного епізоду),
пороги та хеш моделі. За жодною однією метрикою переможця автоматично не оголошуємо.

Порівняння стосується лише цього спрощеного симулятора та вибраних сценаріїв.
Воно не доводить реальної економії електроенергії. Завантажені вимірювання
використовуються для рекомендацій, але не для цієї оцінки: у них немає
наслідків альтернативних дій, потрібних для чесного порівняння економії.

## CLI та API

```bash
# Повний звіт помилок і попереджень без збереження; код 2 при помилках
python main.py validate-data --input examples/readings.json

# Імпорт у власну базу та JSON-експорт (вихідний файл має бути новим)
python main.py import-data --input examples/readings.txt \
  --output /tmp/my-readings.json --db /tmp/my-measurements.db

# Відтворюване порівняння з експортом і збереженням у ту саму історію
python main.py evaluate --episodes 5 --steps 144 --seed 42 \
  --output /tmp/evaluation.json --db /tmp/my-measurements.db

# Тести без зміни наявних даних
python -m unittest discover -s tests -v
```

HTTP API повертає JSON:

| Метод і шлях | Призначення |
| --- | --- |
| `POST /api/validate` | `{ "filename": "readings.json", "text": "..." }` → звіт |
| `POST /api/import` | Те саме тіло → імпорт і рекомендації; 422 при помилках даних |
| `POST /api/evaluate` | `{ "episodes": 5, "steps": 144, "seed": 42 }` → оцінка |
| `GET /api/history` | Останні імпорти та оцінки |
| `GET /api/imports/<id>` | Збережений імпорт із усіма вимірюваннями |
| `GET /api/evaluations/<id>` | Збережена оцінка |

POST-запити використовують `Content-Type: application/json`. Міжсайтові
браузерні POST-запити відхиляються. Назви файлів не використовуються як
шляхи збереження, а сторінка показує дані як текст.
