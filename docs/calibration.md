# Калібрування симулятора за даними датчиків

Модель навчена на спрощеному симуляторі. Команда `calibrate` оцінює параметри
саме вашого будинку з записаних показників, а `--physics` використовує їх для
оцінювання й перенавчання.

```bash
# з живого датчика (тіньовий режим, docs/sensors.md), останні 14 днів
python main.py calibrate --sensor bedroom --hours 336 --output data/user/bedroom-physics.json
# або з файла показників
python main.py calibrate --input readings.csv --output data/user/physics.json --lat 50.45 --lon 30.52

python main.py evaluate --physics data/user/bedroom-physics.json --episodes 12 --seed 20000 --output /tmp/eval.json
python main.py train --method rollout --physics data/user/bedroom-physics.json --no-ui --seeds 42 43 44 \
  --output-dir data/user/training/rollout-my-house
```

За замовчуванням `calibrate` бере погодинну погоду Open-Meteo
([user-data.md](user-data.md#реальна-погода-для-показників)): без реальної
вуличної температури тепловтрати й обмін вологою оцінити не можна.

## Що оцінюється

Пари сусідніх показників з інтервалом 2–30 хв дають швидкості змін. Три
стійкі до викидів лінійні регресії:

| Параметр | Модель | Типове значення симулятора |
| --- | --- | --- |
| `heat_loss_per_h` | dT/dt = k·(T_вул − T) + c | ≈0.093 (з теплоізоляції кімнат) |
| `co2_infiltration_per_h` | dC/dt = −a·(C − 400) + g·n + c₀ | 0 (природного провітрювання немає) |
| `co2_per_person_ppm_h` | g — якщо записано `total_occupants` | 20 |
| `humidity_exchange_per_h` | dH/dt = e·(H_вул − H) + c | 0.05 |

Вільні члени поглинають середні внутрішні надходження (люди, кухня, опалення).
Параметр приймається, лише якщо рушійна різниця достатньо змінювалась, оцінка
значуще додатна (більше двох стандартних похибок) і правдоподібна; інакше
лишається типове значення, а причина потрапляє у `warnings`. Потрібно щонайменше
24 пари; на практиці — кілька діб із різною погодою.

**Обмеження.** Опалення чи вентиляція, що вмикались під час запису, зміщують
оцінки — найкраще калібрувати на періодах без них (або з постійним режимом).
Волога від людей корелює з різницею вологості, тож `humidity_exchange_per_h`
зазвичай занижений (на 19–31 % на синтетичних даних). Параметри застосовуються до
будинку загалом, а не до окремих кімнат.

## Перевірка на синтетичних даних

Тиждень показників симулятора з відомими параметрами (усі пристрої вимкнені,
3 мешканці, 3 різні seed) — `tests/test_calibration.py`:

| Параметр | Істинне | Оцінка (3 seed) |
| --- | ---: | ---: |
| `heat_loss_per_h` | 0.20 | 0.204–0.217 |
| `co2_infiltration_per_h` | 0.50 | 0.538–0.554 |
| `co2_per_person_ppm_h` | 250 | 240–244 |
| `humidity_exchange_per_h` | 0.30 | 0.208–0.244 |

## Наскільки це важливо: модель у «реалістичнішому» будинку

Типовий симулятор дуже оптимістичний щодо CO₂ (людина додає лише 20 ppm/год,
у реальній кімнаті — сотні). Оцінка `rollout-v2` на 12 validation-сценаріях
із параметрами з таблиці вище (`rules_v2`, `comfort_safety_v2`):

| Фізика | Політика | Комфорт, % | кВт·год | Винагорода | Небезпечні кроки |
| --- | --- | ---: | ---: | ---: | ---: |
| типова | `rollout-v2` | 90.30 | 29.37 | 184.29 | 9.67 |
| типова | сильний контролер | 88.34 | 29.26 | 167.69 | 9.67 |
| реалістичніша | `rollout-v2` | 81.50 | 36.27 | 51.61 | 24.25 |
| реалістичніша | сильний контролер | 79.90 | 35.99 | 37.38 | 24.50 |
| реалістичніша | простий контролер | 68.80 | 26.46 | −75.97 | 31.50 |

Перевага моделі над контролерами зберігається, але всі політики стають значно
гіршими, а небезпечних кроків (переважно CO₂ > 1500 ppm) утричі більше.
Тому для реального будинку варто спершу відкалібрувати симулятор і
перенавчити модель з `--physics`.
