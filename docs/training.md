# Навчання покращеної моделі

## Що змінилося

- Симуляція навчання просувається на 10 хвилин за крок, включно з переходом
  доби. Погода, присутність мешканців та часові ознаки використовують цей час.
  `next_state` містить погоду наступного кроку.
- Сценарії змінюють сезон, годину початку, погоду, кількість мешканців,
  температуру, вологість, CO₂, PM2.5 і забруднення. Температури кімнат узгоджені
  з початковою температурою будинку.
- Нові моделі використовують `residual_v1`: **19 дій** замість 1920.
  Дія 0 залишає рішення детермінованого контролера; інші змінюють режим одного
  пристрою (HVAC, вентиляції, очищувача, зволожувача або робота).
  Потім обов’язково застосовуються остаточні правила безпеки.
- Перед RL модель навчається на траєкторіях простого контролера. У цій
  архітектурі експертна мітка — 0 («не коригувати»). Це свідомо гібридна
  система, а не незалежний нейронний контролер. Навчання з підкріпленням
  досліджує корисні відхилення; частина експертних переходів залишається
  в replay із невеликим додатковим imitation loss.
- `comfort_safety_v2` посилює комфорт і вводить явні штрафи за температуру,
  вологість, CO₂, PM2.5 та небезпечні стани. Штрафи за енергію й перемикання
  залишаються. У порівнянні обидва контролери оцінюються тією самою винагородою.
- Після warmup і через задані інтервали модель перевіряється на незмінному
  наборі validation. Зберігається найкращий checkpoint, а не лише останній.
- Можна запускати кілька seed. Переможець обирається за validation **до**
  відкриття test-результатів. Звіт містить середні та стандартні відхилення
  метрик між навчальними seed.

## Запуск

Після встановлення `requirements.txt`, із кореня репозиторію:

```bash
python main.py train --no-ui \
  --seeds 42 43 44 --episodes 200 \
  --warmup-episodes 12 --warmup-epochs 5 \
  --validation-interval 5 --validation-episodes 6 --test-episodes 12 \
  --reference-model data/model.pt \
  --output-dir data/user/training/experiment-01
```

У підготовленому хмарному середовищі замість `python` використовуйте
`/workspace/.venvs/ai-house/bin/python`. Обчислення виконуються на CPU,
типово у 2 потоки; `--threads` дозволяє 1–16. Seed запускаються послідовно.

Швидка перевірка всього циклу:

```bash
python main.py train --no-ui --seeds 42 --episodes 2 \
  --warmup-episodes 4 --warmup-epochs 3 \
  --validation-interval 2 --validation-episodes 2 --test-episodes 2 \
  --output-dir /tmp/house-training-smoke
```

Каталог має бути новим або порожнім: попередній експеримент не перезаписується.
Без `--output-dir` створюється каталог із часом у `data/user/training/`.
Початкова `data/model.pt` та `data/training.db` залишаються незмінними.
Нові артефакти виключені з Git через `data/user/`.

Навчання завжди використовує сезонну синтетичну погоду: поточний API не може
відтворити минулі сезони. `--no-api` залишено як сумісний прапорець.
`--steps` дозволяє 1–144 кроки навчального епізоду; validation і test завжди
мають 144 кроки, щоб скорочене навчання не скорочувало перевірку.
`--warmup-episodes 0` вимикає експертні траєкторії, `--warmup-epochs 0`
вимикає попередню класифікацію; експертний replay у другому випадку залишається.
Типово використовується один seed 42. Для одного seed доступний і Rich dashboard
без `--no-ui`; для кількох — консольний журнал.

## Розділення даних і відбір

| Набір | Роки | Seed сценаріїв | Використання |
| --- | --- | --- | --- |
| Train | 2023–2024 | Залежить від навчального seed та індексу | Warmup і RL |
| Validation | 2025 | Фіксований базовий 10000 | Checkpoint і вибір навчального seed |
| Test експерименту | 2026 | Фіксований базовий 20000 | Фінальна оцінка після відбору |

Місяці циклічно змінюються через 5 місяців, тому 12 сценаріїв охоплюють
усі сезони. Фактичний seed фізики/погоди отримується SHA-256 від набору,
базового seed та індексу. Повний опис кожного сценарію зберігається у звіті.
Train-сценарії warmup та RL мають різні індекси.

Checkpoint і переможець серед seed відбираються лексикографічно:

1. Менше небезпечних кроків.
2. Вищий середній комфорт.
3. Нижче споживання енергії.
4. Вища сумарна винагорода.

Початкова модель після warmup — кандидат `episode=0`. Якщо RL погіршив
результат, `best.pt` може залишитися саме цією моделлю. Це не є доказом,
що RL перевершив прості правила. Порівнюються гібридна політика з правилами
та самі правила; підсумкові метрики потрібно читати разом.

Валідація працює без exploration і повертає початкові epsilon та режим
мережі після перевірки. Її запуски не просувають RNG навчального агента
і не змінюють його ваги чи replay. Результати відтворюються в тому самому
програмному/апаратному середовищі; інші версії PyTorch можуть дати інші результати.

## Артефакти

```text
experiment-01/
  best.pt                    # Переможець за validation серед усіх seed
  selection.json             # Відбір зафіксовано до тестування
  experiment.json            # Фінальні test-результати, розкид між seed, стара модель
  seed-42/
    best.pt                  # Найкращий за validation checkpoint цього seed
    last.pt                  # Останній RL checkpoint
    training.json            # Конфігурація, warmup, навчання та всі validation
    training.db              # Покрокові значення, loss, епізоди й умовний час
  seed-43/...
  seed-44/...
```

Checkpoint містить версію схеми, `action_mode`, кількість дій, версію
винагороди, ваги, optimizer, epsilon, RNG агента й метадані відбору.
Legacy checkpoint без цих полів читається як модель із 1920 абсолютними
діями. Нові й старі моделі використовуються через той самий CLI та вебінтерфейс.

`--resume /path/to/residual/best.pt` — warm start у **новий** експеримент.
Відновлюються ваги, optimizer, epsilon та RNG агента; replay і сценарії
створюються заново, warmup застосовується знову. Це не побітове продовження
попереднього запуску. Legacy checkpoint не можна продовжувати в новому
просторі дій: для нього потрібне нове навчання.

## Використання результату

```bash
python main.py web --model data/user/training/experiment-01/best.pt
python main.py simulate --no-api --model data/user/training/experiment-01/best.pt
python main.py import-data --input examples/readings.json \
  --model data/user/training/experiment-01/best.pt --output /tmp/new-recommendations.json
python main.py evaluate --model data/user/training/experiment-01/best.pt \
  --episodes 12 --seed 20000 --output /tmp/new-evaluation.json
python main.py screenshots --no-api --count 1 --steps 20 \
  --model data/user/training/experiment-01/best.pt --output /tmp/new-screenshots
```

`evaluate` тепер використовує протокол 2: сезонні test-сценарії 2026 року
та `comfort_safety_v2`. Старі й нові результати з різних протоколів/винагород
напряму порівнювати не слід. `--reference-model` у навчальному експерименті
повторно оцінює стару модель на тих самих поточних сценаріях і метриках.

Збільшення кількості епізодів не гарантує покращення. Перевіряйте всі метрики,
розкид між seed та порівняння з правилами. Тести симулятора не доводять
реальної економії чи безпеки фізичного будинку.
