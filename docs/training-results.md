# Перевірений експеримент 23 жовтня 2026

Команда виконана в підготовленому середовищі на CPU з 2 потоками:

```bash
python main.py train --no-ui --seeds 42 43 44 --episodes 30 \
  --warmup-episodes 12 --warmup-epochs 5 \
  --validation-interval 5 --validation-episodes 6 --test-episodes 12 \
  --reference-model data/model.pt \
  --output-dir data/user/training/improved-v2-20261023
```

90 RL-епізодів сумарно, 36 експертних епізодів. Для кожного seed
checkpoint відібрано за 6 validation-сценаріями. Після вибору проведено
оцінку на тих самих 12 test-сценаріях для кожної моделі та старого checkpoint.

Середні значення за test-епізодами, кожен по 144 кроки:

| Метрика | Стара модель | Нова гібридна політика | Простий контролер |
| --- | ---: | ---: | ---: |
| Комфорт, % | 57.83 | 84.55 | 84.55 |
| Енергія, кВт·год | 16.78 | 23.90 | 23.90 |
| Винагорода v2 | −104.14 | 155.73 | 155.73 |
| Кроки поза безпечними межами | 8.50 | 4.08 | 4.08 |

Нижче споживання старої моделі супроводжується нижчим комфортом та більшою
кількістю небезпечних кроків. Нова політика **не перевершила простий контролер**:
для всіх трьох seed найкращим за validation залишився checkpoint після
експертного warmup (`best_episode=0`). Відбір відкинув гірші RL-ітерації.
Тестові метрики між seed збігаються, оскільки обрані політики відтворюють
рішення вчителя; це не доводить незалежного покращення від RL.

Вибрано seed 42 через рівність validation-метрик та стабільний порядок seed.
Checkpoint у поточному середовищі:
`data/user/training/improved-v2-20261023/best.pt`.
Повний звіт: `data/user/training/improved-v2-20261023/experiment.json`.
Для кожного seed збережено і `last.pt`, щоб можна було дослідити подальшу поведінку RL.
Артефакти в `data/user/` локальні й виключені з Git; переносіть їх окремо
або відтворюйте експеримент. Початкова `data/model.pt` не змінена.

Перевірено 19 автоматизованих тестів, імпорт із новою моделлю,
генерацію знімка/навчального звіту та браузерний сценарій: завантаження,
перевірка, рекомендації, пояснення, експорт, історія, оцінка й мобільний вигляд.

Подальша робота над якістю RL потребує окремого експерименту зі збереженням
цього test-набору як звітного, без підбору гіперпараметрів за його результатами.
Порівняння стосується спрощеного симулятора, а не виміряної економії будинку.

Опубліковані копії вибраного checkpoint і звіту доступні в
[`data/models/`](../data/models/README.md). Після клонування запускайте
`python main.py web --model data/models/improved-v2.pt`.

# Експеримент `rollout`, 17 листопада 2026

Метод описано в [training.md](training.md#метод-rollout-перебір-корекцій-і-дистиляція-в-мережу).
Команда (CPU, 4 процеси розмітки, близько 15 хв на seed):

```bash
python main.py train --method rollout --no-ui --seeds 42 43 44 \
  --reference-model data/models/improved-v2.pt --reference-model data/model.pt \
  --output-dir data/user/training/rollout-v2
```

Параметри за замовчуванням: 3 раунди × 48 нових train-сценаріїв (20 736 станів
із оцінками всіх 19 корекцій), горизонт 18 кроків (3 год), температура 0.05.
Відбір раунду, порогу упевненості й seed — лише на 12 validation-сценаріях.
Температуру 0.05 обрано серед {0.05, 0.2} також на validation (seed 42).
Test-результати отримано один раз, після фіксації переможця.

## Що показала діагностика перед експериментом

- Перебір корекцій на копії симулятора над **простим** контролером дав на
  validation комфорт 90.6 % проти 76.6 %, тобто поле для покращення було.
- Проте простий ручний контролер із сильнішими порогами (`tuned`) дав 89.4 %.
  Більша частина «виграшу» над простим контролером — це слабкість його порогів
  (слабкий обігрів узимку, вентиляція 1 при високому CO₂), а не внесок навчання.
  Тому основне порівняння нижче — з `tuned`, а `residual_v2` коригує саме його.

## Результати test (20 сценаріїв на кожен seed набору, 144 кроки)

Seed 20000 — історичний test (12 попередніх сценаріїв + 8 нових індексів);
seed 31000 — нові сценарії, раніше не використані ні для чого.

## Висновки

1. Порівняно з попередньою гібридною моделлю та простим контролером комфорт
   зріс на 9.5–10.9 в.п., небезпечні кроки зменшились приблизно на 45 %
   (6.70 → 3.70 та 9.40 → 5.15), винагорода зросла на 92–101 одиницю. Ціна — +3.1–3.7
   кВт·год за добу: цей компроміс задають ваги `comfort_safety_v2`.
2. Внесок саме навчання — різниця з `tuned`: невелика, але стабільна:
   +1.7 в.п. комфорту одночасно з −1 кВт·год енергії, без погіршення безпеки,
   у 40 з 40 test-сценаріїв.
3. Перший запуск без обмеження монотонності (локально `rollout-v1`) мав схожі
   середні, але в одному test-сценарії 12 небезпечних кроків проти 2: мережа
   вимикала вентиляцію холодної ночі й тримала CO₂ біля 1500 ppm. Після
   заборони корекцій, що послаблюють базу поза комфортом, таких випадків немає,
   а середні результати навіть покращились. Це обмеження варто розглядати як
   частину методу, а не як дрібну деталь.

## Обмеження

- Усе це результати спрощеного симулятора; натурних вимірювань немає.
- Мітки розмітки використовують модель середовища (копію симулятора). На
  реальному будинку для навчання потрібна ідентифікована модель динаміки.
- Пороги `tuned` підібрано вручну до симулятора; ще сильніший контролер
  (наприклад, MPC) міг би зменшити відрив.
- Висновок магістерської «гібридна політика не перевершила детермінований
  контролер» стосується `improved-v2`; для `rollout-v2` він уже не справедливий
  і потребує оновлення разом із розділом про метод.

Checkpoint: `data/models/rollout-v2.pt`, повний звіт із кожним сценарієм:
`data/models/rollout-v2-evaluation.json` (шляхи всередині вказують на локальний
запуск у `data/user/training/rollout-v2/`).

## Висновки

1. **Нічне правило.** Виправлення зменшило споживання всіх політик без втрати
   комфорту: `tuned` −1.5 / −1.8 кВт·год/добу, `rollout-v2` −0.8 / −0.9,
   простий контролер −1.5 / −1.8 (порівняно з таблицею від 17.11 з `rules_v1`).
2. **Тариф.** `rollout-v3-tou` дешевший за `rollout-v2` на 3.3–5.0 % (3.3–4.6
   грн/добу), частково через меншу енергію, частково через перенесення
   споживання на ніч (частка нічної енергії 35–36 % проти 32–33 %). Ціна —
   0.1–0.2 в.п. комфорту. Порівняно з сильним контролером: комфорт +1.5–1.6 в.п.
   і на 3.3–3.6 % дешевше.
3. **Ефект скромніший, ніж можна чекати від «прогріву вночі».** У симуляторі
   тепло втрачається відносно швидко (≈9 % різниці з вуличною температурою за
   годину), а верхня межа комфорту 25 °C обмежує, скільки тепла можна запасти.
   Відчутніший ефект дали б теплоакумулятор, бойлер чи батарея, яких у моделі
   будинку немає.
4. Для пласкої ціни енергії рекомендована `rollout-v2`, для двозонного
   тарифу — `rollout-v3-tou`.

Checkpoint: `data/models/rollout-v3-tou.pt`; повний звіт:
`data/models/rollout-v3-tou-evaluation.json`.
